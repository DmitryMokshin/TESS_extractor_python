# TESS_extractor_python

Питоновский порт [dmitrievdv/Isolated](https://github.com/dmitrievdv/Isolated) (Julia) —
скачивание TESS-вырезок для звезды, построение кривой блеска апертурной
фотометрией с PRF-моделью фона по звёздам Gaia в кадре, чистка кривой от
артефактов и поиск периодов.

Вся переиспользуемая логика лежит в пакете `isolated/` (см. докстринги
внутри модулей). В корне проекта — рабочие скрипты "с запуском": берёте
файл, правите в нём имя звезды/сектор/параметры под своими нуждами и
запускаете. Ниже — в каком порядке их гонять и что каждый делает.

## Окружение

```bash
source .venv/bin/activate   # или используйте .venv/bin/python напрямую
```

Зависимости: `astropy`, `astroquery`, `pandas`, `numpy`, `matplotlib`,
`photutils`, `scipy`, `tqdm` (уже установлены в `.venv`).

## Куда что сохраняется

Все скачанные/промежуточные данные звезды лежат в
`stars_python/{Имя_Звезды}/{ширина}x{высота}/`:

| Файл | Кем создаётся |
|---|---|
| `light_curve_sector_{N}.csv` | `load_light_curve` (сырая кривая: `BTJD, FRAME, CADENCENO, QUALITY, FLUX, FLUX_ERR, MAG, STAR_BKG_RATIO, FLUX_BKG, POS_CORR1, POS_CORR2, CENTROID_X, CENTROID_Y`; старые файлы — `MJD, FLUX, MAG, SN`, читаются через `read_light_curve_csv`, который на лету переименовывает `MJD`→`BTJD` и `SN`→`STAR_BKG_RATIO`) |
| `light_curve_sector_{N}_clean.csv` | `save_clean_light_curve` (после чистки) |
| `light_curve_sector_{N}_trash_frames_{...}.csv` | `save_trash_light_curve` (что вырезано) |
| `periodogram_sector_{N}.dat` / `.png` / `.eps` | `save_periodogram` / `plot_periodogram` |
| `periodogram_sector_{N}_fit.png` / `.eps` | `plot_periodogram_approximation` |

Картинки кривой блеска (`save_lc_figure`) — в `plots/png/{cut}x{cut}/`,
видео-отрывки (`save_cutout_video`) — в `plots/videos/{cut}x{cut}/`.

## ⚠️ Звезда, сектор, размер кадра — у каждого скрипта свои, общего конфига нет

Это "гуляющие" параметры: каждый скрипт хранит их в собственных
константах вверху файла (или, как в `Peridogram_compute.py`, прямо в
блоке `__main__`), ничего не подставляется автоматически между скриптами.
Поменяли размер кадра/звезду/сектор в одном — **обязательно проверьте
остальные**, иначе следующий скрипт в цепочке либо не найдёт файл
(`FileNotFoundError` — путь строится из размера кадра), либо молча
обработает не то, что вы думаете (другой кэш той же звезды под другим
размером, или не тот сектор).

| Скрипт | Звезда | Сектор | Размер кадра |
|---|---|---|---|
| [`run.py`](run.py) | `STAR_NAME` (константа вверху) | выбирается **в терминале** из списка при запуске | `CUT_WIDTH`/`CUT_HEIGHT` (константы вверху) |
| [`TESS_cleaning.py`](TESS_cleaning.py) | `STAR_NAME` (константа вверху) | `TESS_SECTOR` (константа вверху) | `CUT_WIDTH`/`CUT_HEIGHT` (константы вверху) |
| [`Peridogram_compute.py`](Peridogram_compute.py) | `star_name` в блоке `if __name__ == "__main__":` внизу файла | `sector` там же | `cadr_width`/`cadr_height` там же |

Перед запуском пайплайна на новой звезде/секторе/размере — пройдитесь по
всем трём и поправьте синхронно.

## Порядок запуска

### 1. [`run.py`](run.py) — получить данные и первый взгляд на звезду

Отправная точка для новой звезды/сектора. Имя звезды и размер кадра —
константы `STAR_NAME`/`CUT_WIDTH`/`CUT_HEIGHT` вверху файла, а сектор и
видео скрипт теперь спрашивает **в терминале** (Enter — принять значение
по умолчанию в квадратных скобках):

1. находит звезду в Gaia по имени через Simbad (`load_star_gaia_data`), кэширует;
2. находит, в каких секторах TESS её снимал (`find_tess_sectors`), печатает
   список и спрашивает, какой сектор скачать и обработать (ввод проверяется
   — только из показанного списка);
3. скачивает TESS-вырезку и строит кривую блеска выбранного сектора (`load_light_curve`);
4. открывает **интерактивный** просмотрщик кадров + кривой (`plot_cuts`) —
   листаете кадры слайдером/кнопками, ищете глазами провалы, выбросы,
   полосы засветки; здесь же смотрите номера "плохих" кадров для шага 6;
5. сохраняет PNG кривой блеска (`save_lc_figure`);
6. спрашивает, сохранить ли видео-отрывки; если да — спрашивает FPS и
   диапазоны кадров (через запятую, например `2500-2700, 4400-5000`;
   пустой ввод — один клип на весь сектор), затем сохраняет их
   (`save_cutout_video`) — имя файла включает номера кадров, так что клипы
   не перезатирают друг друга.

Перед каждым шагом скрипт печатает блок с текущими настройками (звезда,
сектор, флаг/параметры видео и т.д.), чтобы в логе консоли было видно, с
какими параметрами что выполнялось.

### 2. [`TESS_cleaning.py`](TESS_cleaning.py) — чистка кривой блеска

Один скрипт, чистка в два прохода подряд:

1. **Точечная чистка** — провалы, нули, явные выбросы. `pick_exclusion_windows`
   открывает график кривой блеска, мышью (drag) выделяете плохие участки.
2. **Чистка на уровне кадров** — засветка/полосы от Земли/Луны, которые
   первый проход мог не поймать (например мощный, но короткий выброс,
   который "на глаз" не отличить от настоящей вспышки звезды):
   `pick_stripe_pixels` — листаете кадры, кликаете по фоновым пикселям
   *на полосе, но не на звезде*; `stray_light_monitor_curve` строит по ним
   диагностическую кривую "насколько силён дефект в этом кадре";
   `pick_exclusion_windows` на ней — выделяете всплески; `plot_stray_light_diagnostics`
   рисует 4 панели (кривая звезды / кривая дефекта / их корреляция /
   сравнение кадров), чтобы убедиться, что это дефект, а не вспышка
   (критерии — в комментариях самого скрипта).

Оба набора найденных окон вырезаются **одним** вызовом `exclude_frame_windows`
в конце, а не по очереди. Это принципиально: и точечные окна, и окна с
кадров ищутся по номерам кадров **исходной**, ещё не урезанной кривой; если
резать сначала по одним окнам, а потом по другим уже на урезанной кривой —
номер кадра "съедет" (после удаления строк позиция строки перестаёт
совпадать с номером кадра), и второй проход вырежет не те кадры.
Итог — `save_clean_light_curve`/`save_trash_light_curve`.

### 3. [`Peridogram_compute.py`](Peridogram_compute.py) — поиск частот

Берёт `light_curve_sector_{N}{lc_suffix}.csv`: `lc_suffix = "_clean"` — кривая после
шага 2, `"_prf_clean"` — PRF-кривая из `ss397_localize.py` (без света соседних звёзд).

1. **LS-периодограмма** — быстрый обзор, как раньше, но с вычитанием полиномиального
   тренда (`detrend_deg=2`) и `max_period_fraction=0.5`. Без тренда медленный спад
   потока за сектор даёт ложные пики на 1/T и 2/T. FAP здесь "naive" (белый шум) —
   для статьи не использовать.
2. **Выбеливание** (`isolated/prewhitening.py`): частоты извлекаются по одной, после
   каждой все частоты/амплитуды/фазы и тренд переподгоняются нелинейным МНК.
   Значимость — S/N ≥ 4 относительно локального шума (Breger et al. 1993) и модели
   красного шума (Bowman et al. 2019); ошибки — Montgomery & O'Donoghue (1999) ×√D
   (Schwarzenberg-Czerny 1991). Амплитуды в mmag. Частоты ближе 1/T не допускаются,
   пары ближе 1.5/T помечаются как разрешённые «на грани».
3. **Рисунки**: амплитудный спектр с уровнем 4×шум и спектральным окном, кривая с
   моделью (частоты из выбеливания + тренд), динамический амплитудный спектр
   (окно 10 сут, шаг 0.25 сут).

Выходные файлы (рядом с кривой): `periodogram_sector_{N}{suffix}.dat/.png` (LS),
`..._frequencies.dat` (таблица частот с ошибками и S/N), `..._amplitude.png`,
`..._fit.png`, `..._dynamic.png`. `image_format="eps"` — для публикации.
