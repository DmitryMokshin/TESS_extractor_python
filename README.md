# TESS_extractor_python

Питоновский порт [dmitrievdv/Isolated](https://github.com/dmitrievdv/Isolated) (Julia) —
скачивание TESS-вырезок для звезды, построение кривой блеска апертурной
фотометрией или PRF-деблендингом (свет соседних звёзд Gaia вычитается
отдельной моделью), автоматическая + ручная чистка от артефактов и поиск
периодов с выбеливанием.

Вся переиспользуемая логика лежит в пакете `isolated/` (см. докстринги
внутри модулей). В корне проекта — рабочие скрипты "с запуском": один
общий конфиг (`run_config.py`), дальше запускаете скрипты по порядку.

## Окружение

```bash
source .venv/bin/activate   # или используйте .venv/bin/python напрямую
```

Зависимости: `astropy`, `astroquery`, `pandas`, `numpy`, `matplotlib`,
`photutils`, `scipy`, `tqdm` (уже установлены в `.venv`).

## Один конфиг — [`run_config.py`](run_config.py)

Звезда, сектор(ы), размер вырезки, режим фотометрии и параметры
чистки/частотного анализа — в одном месте, `RunConfig` в `run_config.py`.
`run.py`, `TESS_cleaning.py`, `Peridogram_compute.py`, `PRF_cleaning.py`,
`Peridogram_diagnostics.py` читают его вместо собственных констант. Смена звезды/сектора
на всём пайплайне — одна правка в `CONFIG = RunConfig(...)`. Запуск из
PyCharm кнопкой Run сохраняется: правите значения в файле и жмёте Run на
любом скрипте.

Что специфично для одного скрипта/конкретного исследования (id звезды
сравнения, частоты для карт амплитуд, частоты для сравнения на рисунках,
флаги показа/сохранения графиков) остаётся локальными константами в соответствующем
скрипте, не в конфиге.

Основные поля `RunConfig`:

| Поле | Смысл |
|---|---|
| `star_name`, `sector`, `cut_width`/`cut_height` | звезда, сектор, размер вырезки |
| `sectors` | несколько секторов сразу (по умолчанию не задано → поведение как раньше); если задано, `Peridogram_compute.py` анализирует склеенный ряд |
| `photometry_mode` | `"prf"` (по умолчанию, PRF-деблендинг — рекомендуется для тесных полей) или `"aperture"` (простая апертурная фотометрия) |
| `aperture_radius`, `d_mag_r`, `star_bkg_ratio_min` | параметры апертурного режима |
| `prf_box`, `prf_dt_max`, `prf_merge_px` | параметры PRF-режима |
| `quality_bitmask`, `local_noise_kappa` | правила автоочистки (см. ниже) |
| `nyquist_factor`, `max_period_fraction`, `detrend_deg`, `prewhiten_fmax`, `snr_stop`, `n_max_freq`, `dyn_window`, `dyn_step`, `dyn_frange`, `image_format`, `max_peaks_analyse` | частотный анализ (`Peridogram_compute.py`) |

`CONFIG.lc_suffix` — какой файл кривой блеска соответствует текущему
`photometry_mode` (`_prf_clean` для `"prf"`, `_clean` для `"aperture"`).
`CONFIG.star_dir` — путь до `stars_python/{звезда}/{ширина}x{высота}/`.

## Куда что сохраняется

Все скачанные/промежуточные данные звезды лежат в `CONFIG.star_dir`
(`stars_python/{Имя_Звезды}/{ширина}x{высота}/`). Каждый CSV/`.dat` теперь
несёт шапку-провенанс (`#`-комментарии перед данными): git-хэш, дата
генерации (UTC), число точек и параметры вызова — читатели (`read_light_curve_csv`,
`_read_gaia_csv`) пропускают её прозрачно, старые файлы без шапки читаются
как раньше.

| Файл | Кем создаётся |
|---|---|
| `light_curve_sector_{N}.csv` | `load_light_curve` — апертурная кривая (сырая: `BTJD, FRAME, CADENCENO, QUALITY, FLUX, FLUX_ERR, MAG, STAR_BKG_RATIO, FLUX_BKG, POS_CORR1, POS_CORR2, CENTROID_X, CENTROID_Y`; старые файлы — `MJD, FLUX, MAG, SN`, читаются через `read_light_curve_csv`, который на лету переименовывает `MJD`→`BTJD` и `SN`→`STAR_BKG_RATIO`) |
| `light_curve_sector_{N}_clean.csv` / `_trash_frames_{...}.csv` | `TESS_cleaning.py` → `save_clean_light_curve`/`save_trash_light_curve` (апертурный режим, после авто- и ручной чистки) |
| `light_curve_sector_{N}_prf.csv` | `PRF_cleaning.py`/`isolated.prf_photometry.load_prf_light_curve` — канонический PRF-выход (QUALITY-фильтр, без доп. чистки) |
| `light_curve_sector_{N}_prf_clean.csv` | `PRF_cleaning.py` — PRF-кривая + отбраковка шумных участков (`local_point_to_point_sigma`) |
| `light_curve_sector_{N}{suffix}_log.csv` | `save_cleaning_log` — по каждому выброшенному кадру: номер, время, причина (правило автоочистки или ручное окно); `summarize_cleaning_log` печатает сводку для абзаца «Методы» |
| `periodogram_sector_{N}{suffix}.dat`/`.{png,eps}` | `Peridogram_compute.py` — LS-периодограмма (обзорная, FAP "naive") |
| `periodogram_sector_{N}{suffix}_frequencies.dat` | таблица частот выбеливания с ошибками и S/N |
| `periodogram_sector_{N}{suffix}_amplitude.{png,eps}` | амплитудный спектр (уровень 4×шум + спектральное окно) |
| `periodogram_sector_{N}{suffix}_fit.{png,eps}` | кривая блеска + модель (частоты выбеливания + тренд) |
| `periodogram_sector_{N}{suffix}_dynamic.{png,eps}` | динамический амплитудный спектр |
| `periodogram_sectors_{N1-N2-...}{suffix}*` | то же самое, для склеенных секторов (`CONFIG.sectors`) |

Картинки кривой блеска (`save_lc_figure`) — в `plots/png/{cut}x{cut}/`,
видео-отрывки (`save_cutout_video`) — в `plots/videos/{cut}x{cut}/`.
Диагностика/происхождение сигнала (`PRF_cleaning.py`) — в `out_localize/`
(`amp_maps.pdf`, `attribution.txt`, `comparison_stars.csv`/`.txt`,
`lc_deblended_<id>.csv`, `lc_deblended.pdf`). Углублённый частотный анализ
(`Peridogram_diagnostics.py`) — в `out_tess/`.

## Порядок запуска

### 1. [`run.py`](run.py) — получить данные и первый взгляд на звезду

Отправная точка для новой звезды/сектора. Звезда и размер кадра — из
`CONFIG` (`run_config.py`), а сектор скрипт спрашивает **в терминале**
(Enter — принять значение по умолчанию в квадратных скобках):

1. находит звезду в Gaia по имени через Simbad (`load_star_gaia_data`), кэширует;
2. находит, в каких секторах TESS её снимал (`find_tess_sectors`), печатает
   список и спрашивает, какой сектор скачать и обработать (ввод проверяется
   — только из показанного списка);
3. скачивает TESS-вырезку и строит апертурную кривую блеска выбранного сектора (`load_light_curve`);
4. открывает **интерактивный** просмотрщик кадров + кривой (`plot_cuts`) —
   листаете кадры слайдером/кнопками, ищете глазами провалы, выбросы,
   полосы засветки; здесь же смотрите номера "плохих" кадров для следующего шага;
5. сохраняет PNG кривой блеска (`save_lc_figure`);
6. спрашивает, сохранить ли видео-отрывки; если да — спрашивает FPS и
   диапазоны кадров (через запятую, например `2500-2700, 4400-5000`;
   пустой ввод — один клип на весь сектор), затем сохраняет их
   (`save_cutout_video`) — имя файла включает номера кадров, так что клипы
   не перезатирают друг друга.

Перед каждым шагом скрипт печатает блок с текущими настройками (звезда,
сектор, флаг/параметры видео и т.д.), чтобы в логе консоли было видно, с
какими параметрами что выполнялось.

### 2. Чистка кривой блеска — два режима на выбор

`CONFIG.photometry_mode` решает, какой из двух скриптов гонять на этом
шаге (оба читают ту же вырезку из кэша `run.py`/`load_tess_cutouts`);
`Peridogram_compute.py` дальше сам возьмёт нужный файл через `CONFIG.lc_suffix`.

#### 2a. [`TESS_cleaning.py`](TESS_cleaning.py) — апертурный режим (`photometry_mode="aperture"`)

Простая апертурная фотометрия, чистка в несколько проходов:

0. **Автоочистка** (`auto_clean_light_curve`) — правила по порядку:
   маска `QUALITY` (`CONFIG.quality_bitmask`) → `STAR_BKG_RATIO` ниже
   `CONFIG.star_bkg_ratio_min` (по умолчанию выключено) → локальный разброс
   соседних точек выше `CONFIG.local_noise_kappa` × медианы. Каждое правило
   — на выживших после предыдущего.
1. **Точечная чистка** — провалы, нули, явные выбросы. `pick_exclusion_windows`
   открывает график кривой блеска, мышью (drag) выделяете плохие участки.
2. **Чистка на уровне кадров** — засветка/полосы от Земли/Луны, которые
   первый проход мог не поймать (например мощный, но короткий выброс,
   который "на глаз" не отличить от настоящей вспышки звезды):
   `pick_stripe_pixels` — листаете кадры, кликаете по фоновым пикселям
   *на полосе, но не на звезде*; `stray_light_monitor_curve` строит по ним
   диагностическую кривую "насколько силён дефект в этом кадре";
   `pick_exclusion_windows` на ней — выделяете всплески; `plot_stray_light_diagnostics`
   рисует 4 панели (кривая звезды / кривая дефекта / их корреляция /
   сравнение кадров), чтобы убедиться, что это дефект, а не вспышка
   (критерии — в комментариях самого скрипта).

Оба набора ручных окон вырезаются **одним** вызовом `exclude_frame_windows`
поверх уже автоочищенной кривой, а не по очереди — обе группы окон заданы
по номеру кадра в исходном, ещё не урезанном секторе (колонка `FRAME`), а
не по позиции строки, так что порядок вырезания больше не важен.
Итог — `save_clean_light_curve`/`save_trash_light_curve`, плюс общий
`light_curve_sector_{N}_clean_log.csv` (автоочистка + ручные окна,
`save_cleaning_log`/`summarize_cleaning_log`): по нему можно дословно
восстановить, почему выброшен каждый кадр.

#### 2b. [`PRF_cleaning.py`](PRF_cleaning.py) — PRF-режим (`photometry_mode="prf"`, рекомендуется для тесных полей)

Зачем: в тесных полях апертура собирает чужой свет — например, для SS 397
на цель приходится лишь ≈43 % потока в апертуре r = 3 пикс, на ближайшего
соседа ≈46 % (обе звезды сравнимой яркости). PRF-режим строит модель кадра
как сумму PRF всех звёзд Gaia в окне (положения фиксированы, потоки — один
`lstsq` на все кадры сразу) и выдаёт кривые звёзд по отдельности. И цель, и
её главный "загрязнитель" находятся **автоматически**, никаких Gaia
`source_id` руками задавать не нужно:

1. Цель — через `isolated.data_io.find_target_row` (сопоставление по
   позиции, тот же механизм, что `isolated.prf_photometry.load_prf_light_curve`).
   QUALITY-фильтр (`CONFIG.quality_bitmask`) + PRF-фотометрия
   (`isolated.prf_photometry`, окно `CONFIG.prf_box`×`CONFIG.prf_box`,
   звёзды не слабее `T_цели + CONFIG.prf_dt_max`, звёзды ближе
   `CONFIG.prf_merge_px` пикс к более яркой не фитуются отдельно —
   вырождение, их вклад печатается) → `light_curve_sector_{N}_prf.csv`.
   Доминирующий сосед — звезда поля с наибольшей долей PRF-потока именно в
   апертуре цели (`isolated.photometry.find_dominant_contaminant`, не
   обязательно самая яркая звезда в окне модели вообще) — скрипт печатает
   её `source_id` и долю в консоль сразу же (см. "Правила интерпретации"
   ниже).
2. Отбраковка шумных участков (`local_point_to_point_sigma`) →
   `light_curve_sector_{N}_prf_clean.csv` — дальше используется как
   PRF-эквивалент `_clean.csv`, в том числе `Peridogram_compute.py`.
3. Проверка происхождения сигнала (`isolated.localize`, ROADMAP.md Этап 6):
   свежим выбеливанием находятся значимые частоты цели (`target_freqs`),
   автоматически выбираются звёзды сравнения сопоставимого блеска в
   вырезке, им строятся PRF-кривые тем же методом — сводная таблица
   (`comparison_stars.csv`/`.txt`), есть ли у них частоты цели (если да
   сразу у нескольких — вероятна общая систематика, а не сигнал именно
   цели).
4. Карты амплитуд по пикселям, разложенные по PRF звёзд (`amp_maps.pdf`,
   `attribution.txt`) — видно, какая звезда несёт какую частоту. По
   умолчанию строятся для тех же свежих `target_freqs` из п. 3; чтобы
   посмотреть карту для конкретной кандидатной частоты вместо этого,
   задайте список вручную в константе `AMP_MAP_FREQS_OVERRIDE` в начале
   скрипта.

Метрика загрязнения апертуры (доля потока цели по модели PRF,
`calc_prf_contamination_fraction`) печатается и в апертурном, и в
PRF-режиме; предупреждение, если доля меньше 0.8.

Если `RUN_DIAGNOSTICS_AFTER = True` (константа в самом скрипте, не в `CONFIG`),
сразу после деблендинга разделённые кривые прогоняются через `Peridogram_diagnostics.py`.

#### Правила интерпретации при тесных полях

- **Доля потока цели в апертуре** (`calc_prf_contamination_fraction`,
  печатается в апертурном и в PRF-режиме): ниже 0.8 — апертурной
  фотометрии (`TESS_cleaning.py`) доверять нельзя, нужен PRF-режим.
- **Доля доминирующего соседа**, которую печатает `PRF_cleaning.py`:
  грубые ориентиры — <5 % обычно неважно; 5–20 % стоит иметь в виду при
  сравнении с апертурным режимом; >20 % — загрязнение существенное
  (`PRF_cleaning.py` сам предупреждает об этом в консоли), доверять можно
  только PRF-кривой цели. SS 397 — крайний пример: цель и сосед почти
  сравнимой яркости, доля соседа ≈46–48 %.
- **Вырождение `merge_px`**: звёзды ближе `CONFIG.prf_merge_px` пикс друг к
  другу вообще не разделяются моделью — их поток слит в одну фитуемую
  звезду (в модель попадает более яркая, вклад более слабой печатается, но
  отдельной кривой у неё нет). Если это случилось с самой целью, PRF-режим
  не даёт её независимую кривую — нужно уменьшать `merge_px` (если позволяет
  реальное угловое разрешение PRF) или явно признавать блендинг в тексте.
- **`comparison_stars.csv`/колонка `PRESENT`**: если частота цели
  значима (`PRESENT=True`) сразу у ≥2 НЕ связанных с целью звёзд сравнения
  — вероятна общая систематика поля/инструмента (рассеянный свет и т.п.),
  а не сигнал именно цели. Если частота значима именно у доминирующего
  соседа (а не у случайной звезды сравнения) — это неоднозначно: может
  быть как совпадение (у соседа своя, не связанная с целью, переменность),
  так и остаточная утечка PRF-деблендинга (модель не до конца разделила
  близкие звёзды) — прежде чем делать вывод, сверьтесь с долей `share` в
  `attribution.txt`/`amp_maps.pdf` для этой конкретной частоты.
- **Доля `share` (цель / (цель+сосед)) в `attribution.txt`/`amp_maps.pdf`**:
  ROADMAP.md использует порог ≥0.8 — выше него частота уверенно "сидит" на
  цели по пиксельной карте; ниже — амплитуда на этой частоте распределена
  между целью и соседом сравнимо, происхождение неоднозначно.

#### Как использовать `isolated/localize.py` напрямую

`PRF_cleaning.py`'s `main()` — готовый пример совместного использования
этих функций; для разового исследования (кандидатная частота вне свежих
`target_freqs`, отдельная звезда без прогона всего скрипта и т.п.) их можно
вызывать по отдельности, тем же способом:

- `select_prf_model_stars`/`build_prf_star_cuts`/`deblend_prf_flux`
  (`isolated.prf_photometry`) — построить окно модели вокруг любой позиции
  и получить куб PRF-кривых для всех звёзд в нём (то, что `PRF_cleaning.py`
  делает для цели).
- `deblend_star_curve(cube_good, prf, gaia_stars, cut_width, cut_height, source_id, box, dt_max, merge_px)`
  — то же самое, но окно центрировано на ПРОИЗВОЛЬНОЙ звезде поля по её
  `source_id` (не обязательно на официальной цели пайплайна) — удобно для
  разовой проверки конкретной звезды сравнения или соседа.
- `select_comparison_stars(gaia_stars, target_source_id, cut_width, cut_height, n, mag_tol, box)`
  — список звёзд сопоставимого блеска (в пределах `mag_tol` по T-величине),
  ближайшие по блеску первыми, исключая слишком близкие к краю вырезки.
- `signal_origin_table(star_curves, target_freqs, fmax, snr_threshold)` —
  для списка `[(метка, t, flux_ppt), ...]` и списка частот: амплитуда и
  S/N КАЖДОЙ звезды ИМЕННО на этих частотах (не независимый поиск пиков) —
  строит `comparison_stars.csv`/`.txt`.
- `amplitude_maps(t, cube_box, freqs)` — комплексная карта амплитуды (e/s)
  в каждом пикселе окна для списка частот; `attribute_amplitude(amap, models)`
  раскладывает такую карту по PRF-моделям звёзд окна (`models` из
  `build_prf_star_cuts`), возвращая долю амплитуды, приписанную каждой —
  вместе это и есть "карты амплитуд" `PRF_cleaning.py`, п. 4 выше, но для
  произвольного своего набора частот/окна.

### 3. [`Peridogram_compute.py`](Peridogram_compute.py) — поиск частот

Берёт `light_curve_sector_{N}{CONFIG.lc_suffix}.csv` — `_clean` после
`TESS_cleaning.py` или `_prf_clean` после `PRF_cleaning.py`, в
зависимости от `CONFIG.photometry_mode`. Если задан `CONFIG.sectors`
(несколько секторов), вместо одного сектора анализируется склеенный ряд
(`isolated/multisector.py`, ROADMAP.md Этап 7): каждый сектор независимо
нормируется (вычитается свой медианный уровень) и детрендится (свой
полином) перед склейкой, чтобы разный ноль-пункт и годовые разрывы между
секторами не утекали в самые низкие частоты — каждый сектор при этом
должен уже иметь свою `_clean`/`_prf_clean` кривую (обычный прогон шага 2
на каждый сектор по отдельности).

1. **LS-периодограмма** — быстрый обзор, с вычитанием полиномиального
   тренда (`detrend_deg=2`) и `max_period_fraction=0.5`. Без тренда медленный спад
   потока за сектор даёт ложные пики на 1/T и 2/T. FAP здесь "naive" (белый шум) —
   для статьи не использовать.
2. **Выбеливание** (`isolated/prewhitening.py`): частоты извлекаются по одной, после
   каждой все частоты/амплитуды/фазы и тренд переподгоняются нелинейным МНК.
   Значимость — S/N ≥ 4 относительно локального шума (Breger et al. 1993) и модели
   красного шума (Bowman et al. 2019); ошибки — Montgomery & O'Donoghue (1999) ×√D
   (Schwarzenberg-Czerny 1991). Амплитуды в mmag. Частоты ближе 1/T не допускаются,
   пары ближе 1.5/T помечаются как разрешённые «на грани».
3. **Рисунки**: амплитудный спектр с уровнем 4×шум и спектральным окном (для
   нескольких секторов особенно важно — годовой разрыв даёт сильные алиасы, окно
   показывает их явно), кривая с моделью (частоты из выбеливания + тренд),
   динамический амплитудный спектр (окно 10 сут, шаг 0.25 сут).

`image_format="eps"` (в `CONFIG`) — для публикации.

### 4. [`Peridogram_diagnostics.py`](Peridogram_diagnostics.py) — углублённый частотный анализ

Отдельный, более детальный проход поверх той же числовой части
(`isolated/prewhitening.py`), не завязанный на один режим фотометрии и на
одну звезду: `analyse(<csv>)` работает для любой кривой блеска в формате
пайплайна. `RUNS` в скрипте строится из `CONFIG` и по умолчанию сравнивает
текущий режим (`CONFIG.photometry_mode`), альтернативный режим
(апертура↔PRF, если файл есть) и кривую соседа из `PRF_cleaning.py` (если
считался). На каждую даёт:

- объективный критерий отбраковки инструментальных участков (локальный шум
  точка-к-точке + типичная ошибка потока), а не "на глаз";
- ошибки частот бутстрепом по остаткам и по двум половинам ряда — проверка
  формул Монтгомери–О'Донохью (`bootstrap_frequency_errors`,
  `split_half_frequency_errors`);
- стабильность амплитуд/фаз найденных частот в скользящих окнах
  (`frequency_stability`, `plot_frequency_stability`);
- опция CLEAN (Roberts et al. 1987) для сравнения с программами коллег
  (`clean_periodogram`, `plot_clean_spectrum`);
- комбинационные частоты с допуском по ошибкам, а не просто 0.5/T
  (`find_combination_frequencies`);
- динамический амплитудный спектр для диапазона частот `DYN_FRANGE`
  (константа в скрипте, по умолчанию — тот же `CONFIG.dyn_frange`, что у
  `Peridogram_compute.py`) + трекинг самого сильного пика в нём, амплитуды
  в ppt/mmag;
- опционально `GROUND_OBS_UT` (константа в скрипте, `None` по умолчанию) —
  отметить на графиках окно внешних (например, наземных
  спектроскопических) наблюдений и показать фрагмент кривой вокруг него;
- опционально `COMPARISON_FREQS` (константа в скрипте, пустой список по
  умолчанию) — отметить на рисунках частоты для сравнения из внешнего
  источника (другая публикация, каталог) по этой же звезде;
- LaTeX-фрагмент таблицы частот (`{tag}_freqs.tex`) — готов для вставки в
  текст.

Результаты — в `out_tess/`.
